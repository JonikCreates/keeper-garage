# Keeper v1.1.3 release verification

The release adds ten workbook-backed generations to the existing Enhanced catalog and separates maintenance parts and labor costs without changing historical records.

The source audit reconciles 105 mechanical profiles, 4,072 maintenance rows, 1,112 known-issue rows, and 538 supporting research rows. Trim-specific years, engines, gearboxes, mileage/month intervals, applicability, source URLs, and cautions are retained. Empty user-maintenance templates are not imported as records. Source XLSX files are unchanged; SHA-256 checksums and per-sheet counts are in `v1.1.3-source-audit.json`.

C7 Z51 packages have separate trim choices because the workbook distinguishes wet/dry-sump maintenance. JZX100 early/late gearbox profiles retain explicit build periods for the overlapping 1998 year. These prevent two different schedules from being combined for the same saved configuration.

Source cautions: the C6 workbook applies some later manual references across the generation and contains an ambiguous 2006–2007 T56/TR6060-era description. Some Toyota recommendations use community or period-manual references rather than an exact factory manual for every configuration. Exact build/hardware applicability and VIN/chassis-specific recall completion remain subject to verification. These source caveats remain attached to imported research; this release is not an independent certification of every workbook claim.

## Implementation and compatibility

- `lib/v113VehicleData.ts`, `lib/researchVehicleData.ts`, `lib/enhancedCatalog.ts`, and `lib/catalog.ts` integrate the imports through the existing catalog path. The reproducible importer is `scripts/import-v113-workbooks.py`.
- `src/maintenanceCosts.ts` centralizes integer-cent parsing, validation, split/legacy resolution, and cumulative spending. Split costs take precedence when either column is present, including explicit zero. The cached `cost_cents` is never added again.
- `MaintenanceRecordPanel`, the new `MaintenanceRecordEditor`, `useMaintenanceRecords`, `supabase.ts`, `App.tsx`, and scoped `mechanical.css` styles implement entry, editing, history, and ownership totals. Mutation responses are guarded against a vehicle switch.
- Old records retain their original `cost_cents` and null breakdown. Editing them displays a legacy total, with no invented parts/labor allocation. Existing unsaved single-cost drafts are also preserved.
- `maintenanceExport.ts` includes parts, labor and total for split records and historical totals for legacy records. All saved records contribute, including old records with incomplete work descriptions. Long PDF rows paginate safely. PNG exports share the same detail and total logic.
- `package.json` is the single source for displayed version 1.1.3, via the existing Vite version wiring. This follows the requested release number even though main previously displayed 1.2.0.

## Database deployment

Applied and registered:

1. `20260908120000_add_v113_catalog.sql`: adds exact valid configurations with `ON CONFLICT DO NOTHING`. The generator now preserves previously accepted configurations rather than truncating the allow-list.
2. `20260908121000_split_maintenance_costs.sql`: nullable integer parts/labor columns, bounded cost checks, synchronized cached total, and owner/entitlement-scoped editing of service fields only.

Before/after transaction snapshots verified that existing users, vehicles, maintenance records, tracked maintenance items and entitlements were unchanged, and no previous catalog entries were removed. No historical cost backfill was performed. Test inserts/updates/deletes ran inside rolled-back transactions.

## Verification

- 128 automated tests passed (68 JavaScript and 60 TypeScript).
- All 2,939 selectable catalog configurations passed: no invalid configurations, missing expected data, orphaned research, or cross-configuration leaks.
- TypeScript, ESLint, and production build passed. Vite reports the existing large-bundle warning; no unrelated bundling redesign is included.
- Browser tests exercised parts-only, labor-only, both, neither, split editing, legacy editing, history totals, and deletion. $250 parts + $180 labor = $430; adding a $300 legacy record produces $730.
- Database tests under the authenticated role exercised all four cost combinations and their edits/deletion, legacy preservation, all ten new generations' vehicle creation/reload/removal, vehicle history isolation, export serialization, entitlement checks and ownership boundaries. The manual rollback-only script is `scripts/verify-v113-database.sql`.
- A July historical backfill did not replace an existing August service as most recent. Sorting still prioritizes the service date over the entry timestamp.
- Actual generated PDFs were parsed and visually inspected: the six-case report totals $1,460.00; an eight-record long-note report spans six pages and totals $3,440.00, retaining all eight cost breakdowns.
- Authentication and paid-access regression tests cover existing behavior and database authorization. No real payment or new OAuth account creation was performed. The separate credential-based integration runner requires an isolated test account and was not used.

Release workflow: implemented and tested on debug, then committed and pushed before fast-forwarding main. The final response records the verified commit hashes and remote push results.
